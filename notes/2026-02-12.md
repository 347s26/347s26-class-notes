### Django Ninja
* Let's you create models and talk to your database.
* Connect front end framework to back end framework. Deviation from the templated approach originally in Local Library. 
* In cs 343, with a <\form> tag, we see a GET request, but now if we are making the database we can replace it with other requests.
* Django Ninja is trying to be a REST (Representational State Transfer) framework.
    - Software Architectural Style to describe the design of the architecture of World Wide Web.
    - RESTful APIs:
        - Format: /api/<\modelname> -> HTTP REQUEST
        - EX: /api/book -> GET : Default behavior would list all books, or a specified portion of them
        - /api/book/3 -> GET : Returns books with id 3
        - /api/book/3 -> PATCH : Same URL, different request. This time trying to update the book with id 3, specifically editing.
        - /api/book -> POST : Update list of books, create a new thing, has a payload
            --extra http requests you may have enountered: 
                GET, POST, PUT, PATCH, DELETE
* Django Ninja provides a ModelSchema:
    - Automatically generates schemas for you, which are customizable for each use case.
    - You can override different fields or add new ones as needed.
    But for why?
    - Different ways to look at and share the data. The user would not need to know all the internal modeling, 
        maybe only needed to be shared with the database. 
    - Different ways to request items from schema: all, include, exclude
